**2026.08 - 2026.10**
**电商商品管理后台（含运营数据大屏）- 前端 / 全栈独立开发**　【新】

项目概述：面向电商运营的商品管理后台，覆盖「三级分类 → 品牌 → 平台属性 → SPU → SKU」商品建档全流程与上架管控，并配套 RBAC 权限体系与实时运营数据大屏；独立完成前端全部页面与交互、后端 12 个模块的 REST 接口。

核心难点：① 权限需在菜单 / 按钮 / 接口三级统一裁决，且不能出现刷新丢菜单；② 千条级待办清单全量渲染会撑爆 DOM，并把大屏整页顶长；③ ECharts 图表库体积大，不能进入首屏。

技术栈实现：Vue 3.5 + TypeScript + Vite + Pinia + Vue Router + Element Plus + ECharts 6｜Express 5 + MongoDB + JWT｜pnpm Monorepo。

主要工作：

· **权限体系前端闭环**：菜单采用「静态路由 + meta.code 过滤」而非 addRoute 动态注册，从根上规避动态路由刷新丢失的持久化与竞态问题；按钮级用 v-permission 指令做 display 切换（可逆、不破坏 vnode 对账），配合路由守卫与 axios 401/403 拦截形成三级统一裁决，真正裁决权仍在后端 requirePermission 中间件（fail-closed 兜底）；

· **虚拟列表与长清单性能**：为千条级运营待办手写固定行高虚拟列表 —— 轨道高度 = 总行数 × 行高撑出滚动范围、窗口整体 translateY 平移、上下各 overscan 3 行；DOM 与数据量解耦后，1000 条数据仅渲染 21 行 / 261 个 DOM 节点（全量渲染约 11,030 个），经 Chrome DevTools Protocol 探针实测滚动定位漂移 0.00px；并用 CSS contain: size 断开「内容 → 面板高度」耦合，长清单不再撑高整页布局；

· **组合式函数抽象**：沉淀 usePagedList / useFormSubmit / useDeleteConfirm / useLatestRequest 四个 composable —— 分页列表内置「删空页自愈」（删除后越界自动回退最后一个非空页）、表单提交骨架统一 9 处表单与抽屉（校验 → 前置处理 → loading → 成功回调，前置产物经类型系统透传）、请求竞态用序号令牌只认最后一次响应，消除各 CRUD 页面的重复逻辑；

· **构建体积与运行时调度**：ECharts 按视图注册（只 import 用到的图表与组件，图表库 588KB 落入大屏独立 chunk 不进首屏）+ 路由级懒加载；keep-alive 以 keyed fullPath 精确缓存列表页筛选状态；大屏 30s 轮询并在标签页隐藏时自动暂停，避免后台标签页空转；

· **接口设计与数据口径**：商品域以销售属性笛卡尔积生成 SKU，配套维度 / 组合去重、期望组合数上限与唯一索引冲突兜底（并发重复生成返回 409 而非 500）；设计「无价不可上架」闸门并校验生效后状态，同时拦截「上架未定价」与「在架改价为 0」两条路径，从接口层杜绝脏数据流入运营侧；

· **工程规范**：pnpm workspace 单仓管理前后端，husky + commitlint + lint-staged 约束提交规范；双端 TypeScript 严格模式并将 type-check 纳入交付流程；样式全量令牌化（颜色 / 间距 / 字号 / 圆角走 CSS 变量，ECharts 与 CSS 共用同一份设计令牌，杜绝硬编码）。

## 三、逐条自检：难点 / 方案 / 效果 + 怎么测的

> 标准：每段 15 秒能说清「难点—方案—结果」，且每个数字都能答出「怎么测的、基准是什么」。

### ① 权限体系前端闭环

- **难点**：三级统一裁决 + 刷新不丢菜单。**方案**：静态路由过滤而非 addRoute + v-permission 指令 + 守卫/拦截器。**效果**：无动态路由持久化与竞态、菜单与可达性同源。
- **会问**：为什么不用 addRoute？（★ 本条最值钱的追问）
- **15 秒版**：动态注册路由刷新会丢路由表，得持久化重建还容易和守卫竞态；我把路由表写死、每项挂 meta.code，登录后用后端 codes 过滤菜单，菜单显隐和路由可达性判断的是同一份数据；按钮级只是体验层，真正裁决永远在后端 403。
- **出处**：`stores/permission.ts:11`、`router/routes.ts:3-6`、`directives/permission.ts:4-11`、`router/guards.ts:75`。

### ② 虚拟列表与长清单性能

- **难点**：千条待办撑爆 DOM + 把整页顶长。**方案**：手写固定行高窗口化 + 实测行高 + `contain: size`。**效果**：261 vs 11,030 节点、漂移 0.00px、整页不再被撑高。
- **怎么测的**：headless Chrome + Chrome DevTools Protocol 探针 —— 注入脚本读真实 DOM（数行数、TreeWalker 数节点），每次滚动后比对「首行坐标」与「(序号-1) × 行高」，差值即漂移；基准 = 同数据量不做窗口化的理论节点数（行数 × 单行 11 节点 + 固定开销）。
- **会问**（三个经典追问，答案如下）：
  - **边界处理**：首帧行高为 0 时先渲染 1 行量出高度再开窗；滚到底留 1px 容差撤掉渐隐；数据不足一屏时不滚动。
  - **白屏**：上下各 overscan 3 行，滚动时不至于滚进未渲染区域；窗口用 translateY 整体平移，走合成层不触发布局。
  - **滚动抖动 / 定位漂移**：行高实测（含 margin-bottom 行距）而非公式估算 —— 字号带 clamp 随视口变、窄视口下标签高度会反超文本行，估算差零点几像素滚几百行就累积成可见错位。
  - **为什么不用现成库**：固定行高只读列表，手写不到 60 行；库的优势在不定高/多列场景，这里用不上。
- **出处**：`views/screen/components/SkuTodoList.vue:27-88`（`contain: size` 在 `views/screen/index.vue` 的 `.todo-panel`）。
- **【风险提示】**：讲不清 CDP 就把「经 Chrome DevTools Protocol 探针实测」改成「实测」，保留数字、去掉接不住的工具名。

### ③ 组合式函数抽象

- **难点**：CRUD 页面重复逻辑 + 快速操作下的请求竞态。**方案**：4 个 composable + 序号令牌。**效果**：9 处表单共用提交骨架、删空页自动回退。
- **会问**：useLatestRequest 和防抖 / 取消请求的区别？（★ 必背）
- **15 秒版**：它**不是防抖**（不减少请求数，点击类触发不该防抖），也**不是取消**（过期请求仍跑完，只是结果和 loading 收尾被丢弃）；实现是一个自增序号，响应回来 `current !== seq` 就丢弃；语义是「场景内只认最后一次响应」。
- **出处**：`composables/useLatestRequest.ts:5-11`（三条语义边界注释）、`usePagedList.ts:22-35`、`useFormSubmit.ts:4-8`。

### ④ 构建体积与运行时调度

- **难点**：图表库体积大，不能进首屏。**方案**：按视图注册 + 路由懒加载 + 轮询调度。**效果**：588KB 独立 chunk、后台不空转。
- **怎么测的**：`vite build` 产物分析 —— ECharts 相关代码全部落在大屏路由的独立 chunk，首屏 chunk 不含；「588KB」是该 chunk 的实际体积。
- **会问**：按视图注册具体省了什么？→ 只 import 4 种图表（折线/柱状/饼/热力）与对应组件（Grid/Tooltip/Legend/VisualMap），而不是整包引入。
- **出处**：`utils/echarts.ts`、`views/screen/index.vue` 轮询模块。

### ⑤ 接口设计与数据口径

- **难点**：组合爆炸 + 并发写重 + 脏数据上架。**方案**：期望组合数上限、唯一索引兜底 409、生效后状态校验。**效果**：两条脏数据路径都被拦。
- **会问**：维度多组合爆炸怎么办？为什么重复生成报错不覆盖？闸门跟前端按钮置灰的区别？
- **【风险提示】**：这是后端题。**投纯前端岗、且答不上来后端细节，就删掉这条。**

### ⑥ 工程规范

- **难点**：协作与交付无硬约束。**方案**：Monorepo + 提交规范 + 双端类型 + 样式令牌化。**效果**：仓库内有可查证的配置与提交记录。
- **定位**：**基本功信号，不是亮点**，放最后，版面紧张第一个删。
