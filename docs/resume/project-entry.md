## 一、标准版（推荐，3 条）

**电商商品后台管理系统（商品中台 + RBAC 权限 + 数据大屏）**　个人项目 · 独立开发　2026.08 – 2026.10
技术栈：Vue 3.5 / TypeScript / Vite / Pinia / Vue Router / Element Plus / ECharts 6 / Express 5 / MongoDB / JWT / pnpm Monorepo

**项目背景**：面向电商运营的商品管理后台，覆盖「三级分类 → 品牌 → 平台属性 → SPU → SKU」建档全流程与上架管控，配一套 RBAC 权限体系（菜单 / 按钮 / 接口三级生效）和一块商品运营数据大屏。前后端分离，独立完成从数据建模、接口设计到前端实现与测试的全部工作（前端 8600+ 行、后端 4100+ 行）。

- **商品建档链路**：基于销售属性维度**笛卡尔积**自动生成 SKU，配合维度/组合去重校验与唯一索引冲突兜底（并发重复生成返回 409 而非 500），并设计「无价不可上架」闸门（校验生效后状态、拦截在架改价为 0），从接口层杜绝脏数据流入运营侧。
- **RBAC 权限体系（动态路由版）**：权限模型对齐若依拆分为权限标识 / 路由地址 / 组件路径等字段，后端一次聚合下发授权路由树，前端静态壳 + `addRoute` 运行时注册（守卫重放时序 + 登出物理摘除，修复 `redirectedFrom` 失效 name 致重放误判的 bug）；403 自愈让权限变更无需刷新即时收敛；编写 168 例接口边界测试（越权 / 边界值 / 契约 / 祖先补全 / 迁移）锁定内置角色、grant-super、最后一名超管三项特权保护。
- **数据大屏**：ECharts 按视图注册 + 独立 chunk 懒加载（588KB 图表库不进首屏），30s 轮询并在标签页隐藏时暂停；待办清单手写固定行高虚拟列表，1000 条数据下 DOM 稳定在 21 行 / 261 节点（常规全量渲染约 11,030 节点），滚动定位漂移实测 0.00px；并用 `contain: size` 断开「内容 → 面板高度」耦合，长清单不再撑高整页。

## 四、面试防线（每个数字的出处与追问应答）

> 原则：简历上写下的每个字都要能被追问三层。下面是本次写进简历的每条主张的「出处 + 最可能的追问 + 真实答案」。

### 1. 「笛卡尔积生成 SKU / 去重校验 / 409」

- **出处**：`backend/src/services/sku.ts:86` 笛卡尔积函数；`:129` `Sku.exists({spuId})` 重复生成 409 安全网；`:153/:225` 维度重复、组合重复校验；`:160` 期望组合数上限；`:286` 唯一索引冲突 `rethrowConflict` → 409。
- **追问：维度多了组合爆炸怎么办？** 答：有 `MAX_COMBINATIONS` 上限，先算期望组合数（各维度取值数连乘），超限直接 400 拒绝，不让一次请求把库写爆。
- **追问：为什么重复生成要报 409 而不是覆盖？** 答：生成是一次性操作，重跑会覆盖运营已经填好的价格和库存 —— 这是数据事故，所以宁可报错让运营显式清空再生成。
- **追问：并发下两个请求同时生成呢？** 答：SKU 有（spuId + 销售属性组合）的唯一索引，第二个请求会命中索引冲突，被捕获转成 409，不会产生半截数据也不会 500。

### 2. 「无价不可上架闸门」

- **出处**：`backend/src/services/sku.ts:242` 逐行校验；`:345` 注释「拦截生效后状态而非请求体」；`:354-358` 显式上架未定价 / 在架改价为 0 两种路径分别给文案。
- **追问：和前端按钮置灰有什么区别？** 答：前端置灰只是体验，接口才是闸门 —— 闸门校验的是「请求生效后这条 SKU 的状态」，所以它能同时拦住两条路：直接调接口上架未定价 SKU，以及把在架 SKU 的价格改成 0（前端表单改价和上架是两个按钮，只在按钮上判断会漏掉后者）。

### 3. 「164 例边界测试」

- **出处**：`backend/scripts/boundary-test.ts`，模块分布：SKU 51 / 权限与 RBAC 32 / SPU 18 / 用户 13 / 品牌 9 / 角色 8 / 属性 6 / 注册 5 / 大屏 5 / 分类 4 / 个人资料 3 / 改密 3 / 登录 2 / 上传 2 / token 与销售字典 3。
- **追问：覆盖了哪些类型？** 答：四类 —— 越权（无 token / 伪造 token / 无权限用户）、边界值（价格分档下闭上开、笛卡尔积空集）、契约（字段形状、大屏数值与直连库比对）、并发（重复生成 SKU）；外加内置角色 / 超管这类软约束的保护断言。
- **【风险提示】如被问「都通过了吗」**：如实说 —— 164 例里当前 163 例通过，1 例红的是**测试前提过期**（注释还写「新注册用户只有 /home /screen 权限」，但库里默认角色已加了商品权限，于是请求没走到 403 而是因缺参数返回 400），是断言没跟上权限数据变化，不是接口缺陷；已定位修法（换成该角色确实没有的接口，或补上参数再断言 403）。**这句话讲出来是加分项**，比含糊过去强。

### 4. 「虚拟列表：21 行 / 261 节点 / 漂移 0.00px」

- **出处**：`vue-project/src/views/screen/components/SkuTodoList.vue`；实测数据由 headless Chrome + CDP 探针测得（数据 12 / 96 / 300 / 1000 条时 DOM 分别渲染 12 / 21 / 21 / 21 行，单行 11 个节点，上限 261 节点；常规全量渲染同数据下为 162 / 1086 / 3330 / 11030 节点）。
- **追问：为什么不用现成的虚拟列表库（vue-virtual-scroller、el-table-v2）？** 答：需求是「固定行高的只读列表」，手写核心只有三件事 —— 轨道高度 = 总行数 × 行高撑出滚动范围、窗口整体 `translateY(startIndex × 行高)`、上下各 overscan 3 行防露白；不到 60 行代码，比引一个库（额外依赖 + 样式定制成本）更划算。库的优势在不定高 / 海量列，这里用不上。
- **追问：行高为什么必须实测不能写死？** 答：字号带 `clamp(11px, 0.72vw, 13px)`，行高随视口变化；而且量的时候必须把行距（写在 `margin-bottom` 上的 5px）一起算进去，少算一个行距，滚几百行就累积成肉眼可见的错位。
- **追问：不定高的列表怎么办？** 答：当前明确不做 —— 不定高要引入估计高度 + 实测回填 + 滚动锚定，复杂度上一个量级；这条数据行高由 CSS 完全决定，属于「可以被固定」的场景，硬上不定高方案是过度设计。
- **追问：滚动条藏了怎么操作？** 答：容器可滚（滚轮 / 触摸），并给了 `tabindex="0"` 支持键盘滚动、`role="list"` + 每行 `aria-posinset/aria-setsize` 补回「第 N 条 / 共 M 条」的结构信息（只渲染窗口内行时读屏拿不到），底部用渐隐提示「下面还有」、滚到底自动撤掉。

### 5. 「contain: size 断开耦合」

- **出处**：`vue-project/src/views/screen/index.vue` `.todo-panel { flex: 1; min-height: var(--dash-todo-min-h); contain: size; }`。
- **追问：为什么不用 `max-height` 封顶？** 答：先试的就是 `max-height` —— 实测在 1920×1080 下它会让面板提前收边，右列下方空出 117px 空洞（面板 496.8px vs 右列 613.64px）；`contain: size` 让面板高度完全由网格列决定（内容不再参与），两个问题一起解决。
- **追问：`contain: size` 有副作用吗？** 答：有 —— 元素内在尺寸归零，浏览器不再按内容给它高度，所以必须显式给高度：宽屏下由右列 flex 拉满，≤768px 单列断点下由 `min-height: clamp(320px, 46vh, 560px)` 兜底。

### 6. 「588KB 不进首屏」

- **出处**：`vite build` 产物分析 + `vue-project/src/utils/echarts.ts` 按视图注册（只 import 用到的图表类型与组件）+ 路由懒加载（大屏是独立 chunk）。
- **追问：怎么证明没进首屏？** 答：构建产物里 ECharts 相关代码全部落在 `/screen` 路由的独立 chunk 里，首屏（登录 / 首页）的 chunk 不含它；按视图注册又把 ECharts 全量（约 1MB）削到 588KB。
